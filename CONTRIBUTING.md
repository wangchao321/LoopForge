# Contributing

LoopForge is currently at the project-definition stage. Start with README.md, docs/PRODUCT.md and docs/ROADMAP.md. Setup commands will be added when the first application milestone is implemented.

Use small branches and pull requests tied to a problem, expected behavior and acceptance criteria. Include relevant verification evidence and call out anything that remains unimplemented.

For workflow changes, describe affected states, actor permissions and existing-data implications. For AI features, include examples of insufficient evidence and human review. For releases, verify that artifacts and approvals refer to the same scope revision and build.

Use only synthetic examples in public issues, screenshots, fixtures and documentation. Keep customer records, credentials, real packages and internal product materials outside the public repository.

Public visibility does not select a license. A project-owner license decision is pending.
